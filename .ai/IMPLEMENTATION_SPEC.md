## 1. Scope

`src/aas_bridge/` layout (distribution **`aas_bridge`**, CLI command **`aas_bridge`**) with

`@context`), (b) the V3.0→V3.1 upgrade transformation (namespace-declaration re-label,

**Behavioral decisions this SPEC implements (debated and approved by the human, 2026-11-18):**

- A v3.1 input produces a first-class **"already AAS 3.1 — no migration needed"** result:
  exit 0, no output file, no gate run (TD-001/TD-002).
- The evidence gate uses a **same-venv pip swap** orchestrated by the tool: the main process
  NEVER imports basyx; every basyx load runs in a subprocess after `pip install` of the
  required version; the venv is always restored to `basyx-python-sdk ~= 2.2` (ADR-021).
- Baselines are cached by (file sha256, basyx version) under `aas-bridge_CACHE_DIR` so
  repeated migrations do not re-swap; the first gate run on a new file may need network for
  pip (accepted, documented deviation from strict offline-first — `check` stays fully
  offline).
- The CLI reports in English or Spanish via `--lang {en,es}` (auto-detect from system locale,
  fallback `en`). The roadmap acceptance "prints the diagnosis in English and Spanish" is
  interpreted as *available in both* via the flag (TD-001/TD-002).
- **`migrate --report <path>` persists the refusal report when the gate refuses** (outcome
  `refused`, gate `fail`): fail-closed evidence is retained on disk (ISS-007, TD-002).

## 3. Interfaces / Data

**Public Python API (stable; changes require a decision, L2-18).** Pure functions and
dataclasses; no side effects on import; type hints on all public functions. All imports
(internal and tests) use `aas_bridge.*`; the gate loaders live at
`aas_bridge.engine._loaders.*`:

- `aas_bridge.registry.versions`
  - `AAS_VERSION_IRIS: dict[str, str]` — labels to IRIs: `"3.0" -> "https://admin-shell.io/aas/3/0"`, `"3.1" -> "https://admin-shell.io/aas/3/1"`
  - `DIALECT_MAP: dict[str, str]` — `"3.0" -> "basyx-python-sdk==2.0.1"`, `"3.1" -> "basyx-python-sdk~=2.2"` (evidence: `ECOSYSTEM_COMPATIBILITY.md` §1, §4)
- `aas_bridge.engine.detect`
  - `@dataclass PartDetection`: `part_name: str`, `format: Literal["xml", "json"]`, `declared_version: str | None` (full IRI), `version_label: str | None` (`"3.0"`/`"3.1"`)
  - `@dataclass DetectionResult`: `file: str`, `parts: list[PartDetection]`, `consistent: bool`, `version_label: str | None` (`None` = undetectable/inconsistent)
  - `detect_versions(path: Path) -> DetectionResult` — raises `DetectionError` (actionable) on: not a ZIP/OPC package, no aasx-origin relationship, no aas-spec parts. XML: parse xmlns **declarations** only, both `xmlns="..."` (corpus v3.0 form) and `xmlns:aas="..."` (corpus v3.1 form); versioned external IRIs in **value** positions (IEC 61360 `.../DataSpecificationTemplates/.../3/0`) are NOT declarations and must never match. JSON: read top-level `@context`; report the declared IRI if present, else `declared_version=None` ("undetectable" — basyx-written JSON carries no marker, evidence §4.6 J3).
- `aas_bridge.engine.transformer`
  - `@dataclass TransformResult`: `output_path: Path`, `rule_id: str`, `parts_touched: list[str]`
  - `transform(source: Path, target_ns: str, output_dir: Path | None = None) -> TransformResult` — applies `v3_0_to_v3_1/namespace-relabel` to every XML aas-spec part; rewrites **declarations only**; rebuilds the OPC/ZIP preserving every other part, `[Content_Types].xml`, `_rels`, supplementary parts, thumbnails, BOMs and compression byte-for-byte; writes `<stem>-adapted.aasx` next to the input (or in `output_dir`); never opens the input for writing; raises `MigrationError` on any JSON aas-spec part (fail-closed message per §4.6), unknown/unapproved rule, or rebuild mismatch.
- `aas_bridge.engine.gate`
  - `@dataclass MigrationOutcome`: `status: Literal["emitted", "no_migration_needed", "refused"]`, `report: MigrationReport`, `output_path: Path | None`
  - `run_migration(source: Path, report_path: Path | None = None, generated_at: datetime | None = None) -> MigrationOutcome` — full pipeline: lock → detect → plan → (no-migration shortcut) → baseline → transform → target load + round-trip → emit-only-on-pass. Raises `ProbeError` on pip/subprocess failure (actionable, both basyx versions named), `EvidenceGateError` on baseline mismatch. When the gate refuses and `report_path` is given, the refusal report is persisted (outcome `refused`; ISS-007, TD-002).
  - Baseline comparison: total object count, per-kind counts (AAS/Submodel/ConceptDescription), `sha256("\n".join(sorted(ids)))`, `sha256("\n".join(sorted(semantic_ids)))`. A baseline of **0 objects is a gate failure** (guards the silent-empty-store mode, evidence §4.2).
- `aas_bridge.engine.report`
  - `@dataclass MigrationReport`: `schema_version: int = 1`, `tool_version: str`, `generated_at: datetime` (ISO 8601), `source` (file, sha256), `detected` (per-part), `target` (label, namespace, basyx_version), `rules_applied: list[str]`, `baseline` (basyx_version, counts, id/semanticId hashes), `gate` (result, target counts, round_trip), `outcome` (status, output_file)
  - `to_json() -> str` (UTF-8, snake_case, deterministic key order, no NaN/Infinity), `from_json(str) -> MigrationReport`
- `aas_bridge.exceptions`: `aas-bridgeError(Exception)`; `DetectionError`, `MigrationError`, `EvidenceGateError`, `ProbeError`, `IngestError` all subclass it.

**CLI contract (public, TD-002).** Kebab-case commands/flags; exit codes per
`CONVENTIONS.md` §2 (`0` success incl. no-migration; `1` user/input error (missing file, not
an AASX, undetectable, JSON parts); `2` usage error; `3` gate failure; `4` internal error):

```
aas-bridge --version                  # prints "aas-bridge 0.1.0"
aas-bridge check <file> [--lang {en,es}]
aas-bridge migrate <file> [--lang {en,es}] [--report <path>]
```

`--lang` default: system locale when `en`/`es`, else `en`. Every user-facing string exists in
both locales in `src/aas_bridge/cli/i18n.py` (stable keys); AAS technical terms stay in
English; the `--version` banner is `"aas-bridge {version}"` (ADR-024). Errors state **what
failed, why, and what to do next**, naming both versions when relevant. The CLI maps
exceptions to exit codes; library code uses `logging`, never `print`. `--report` persists the
JSON report for `emitted` **and** `refused` outcomes (ISS-007).

**Invariants (violations are review FAILs):** basyx is the only validator (L1-9); the main
process never imports basyx (ADR-021); the target namespace comes from the installed basyx
(`NS_AAS` via `dialect_probe`), never hardcoded, and the gate fails closed if it does not
match the registry's expected target IRI; never mutate the input; emit only on gate pass;
the corpus folders are read-only.

**Must not change:** corpus files; `.ai/` law/context files beyond the ai-layer rows in §2;
the exit-code table; the JSON report keys once golden fixtures land; the cache dir name and
`aas-bridge_CACHE_DIR` (unchanged by ADR-024).

### Step 5 — Evidence gate

- **Recommended skill:** `basyx-evidence-gate` — **with one override:** the skill's
  ephemeral-venv pattern is superseded by ADR-021 (same-venv pip swap). The skill's core
  principles (baseline before / compare after / round-trip / emit-only-on-pass / tested in
  both pass and fail directions) apply unchanged.
- **Target files:** `src/aas_bridge/engine/gate.py`,
  `src/aas_bridge/engine/_loaders/__init__.py`,
  `src/aas_bridge/engine/_loaders/dialect_probe.py`,
  `src/aas_bridge/engine/_loaders/baseline_loader.py`,
  `src/aas_bridge/engine/_loaders/target_loader.py`, `tests/unit/test_gate.py`,
  `tests/integration/test_gate_corpus.py`
- **Instructions:**
  - **Subprocess contract:** each loader is runnable via `python -m`, reads arguments from
    argv, prints one JSON object to stdout, exits non-zero with an actionable message on
    stderr. `dialect_probe`: installed basyx version (via
    `importlib.metadata.version("basyx-python-sdk")` — basyx has no top-level `__version__`,
    ISS-008) + `NS_AAS` (imported from `basyx.aas.adapter.xml`). `baseline_loader`:
    `AASXReader` (failsafe=False on the final object store check) load of the original →
    per-kind counts, sorted-ID/semanticId hashes; **0 objects → failure** (guards the
    silent-empty-store mode). `target_loader`: load the adapted file → same metrics; then
    round-trip (re-serialize the store with `write_aas_xml_file` to bytes, re-load,
    re-compare).
  - **Swap orchestration (`gate.py`):** acquire an exclusive lock file in the cache dir
    (O_EXCL; stale after 30 min → break with a warning; release in `finally`); resolve the
    baseline dialect from `DIALECT_MAP` by detected label; run `pip install
    basyx-python-sdk==2.0.1` (timeout 600 s) → `baseline_loader` subprocess (120 s) →
    **always restore `pip install "basyx-python-sdk~=2.2"` in `finally`**; then
    `dialect_probe` (no swap needed — venv already at target) → verify reported `NS_AAS`
    equals the registry target IRI, else fail-closed `EvidenceGateError`; transform; then
    `target_loader`; compare against baseline (counts + both hashes); emit only on pass. All
    pip/subprocess failures raise `ProbeError` naming both versions and the exact manual
    recovery command.
  - **Baseline cache:** JSON files under the cache dir; key = sha256 of the input file;
    entry records basyx version + baseline metrics; a hit skips the swap entirely. Cache

## 7. Stop Triggers

- If a path, interface, schema or step is missing or ambiguous: append `[SPEC-AMBIGUITY]` to
  `history/ISSUES.md` and stop.
- If the task requires a structural change outside this SPEC (e.g. creating
  `src/aas_bridge/gui/`, touching `probes/`, adding a dependency): stop and escalate to the
  architect.
- If any module, import or path still references `aas-bridge.*`, `../src/aas_bridge/` or the
  stale root `aas-bridge/` after the consolidation: stop (`[SPEC-RENAME-DRIFT]`).
- If a forbidden dependency or an unapproved network need appears (beyond the declared pip
  swap of `basyx-python-sdk` 2.0.1/~=2.2 in the gate and integration tests): stop and
  require a decision.
- If the gate cannot restore the venv to `~=2.2` (pip failure mid-swap): fail-closed, record
  a `[BLOCKER]` issue with the exact recovery command, and stop the cycle.
- If any test or manual step would write inside `aas_v3-0/` or `aas_v3-1/`: stop
  (`[SPEC-CORPUS-MUTATION]`). Always copy to `tmp_path`/scratch first.
- If the installed basyx dialect reported by `dialect_probe` does not match the registry
  target (`https://admin-shell.io/aas/3/1`): refuse the migration (fail-closed) — never
  transform against an unverified dialect.
- If `ui_scope: none` is violated (UI files in the diff): stop (`[SPEC-UI-DRIFT]`).
- If a CLI user-facing string is missing in either locale: stop; never ship a partial
  catalog.
